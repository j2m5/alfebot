# Диалоги во флудилке

## Провайдер модели

Основной провайдер — NVIDIA Build. В `.env` нужны `LLM_PROVIDER=nvidia`,
`NVIDIA_API_KEY` и `NVIDIA_MODEL=nvidia/nemotron-3.5-super-vl-120b-a12b`.
Ключ создаётся в [NVIDIA Build](https://build.nvidia.com/); `.env` не попадает в Git и Docker-образ.
После изменения окружения контейнер нужно пересоздать:
`docker compose -f docker/docker-compose.yml up -d --build`.

Для резерва оставлены `LLM_FALLBACK_PROVIDER=openrouter`, `OPENROUTER_API_KEY` и
`OPENROUTER_MODEL=nvidia/nemotron-3.5-super-vl:free`. При HTTP 429/5xx или ошибке
соединения до получения успешного ответа бот один раз обращается к резерву
с тем же сигналом отмены. Перед этим HTTP 503 основного NVIDIA один раз повторяется
через секунду: у сервиса проверки контента наблюдались кратковременные сбои,
после которых тот же запрос проходил успешно. Лимит 429 не повторяется.
Начавшийся поток, частичные вызовы инструментов,
ошибки запроса/авторизации и отменённые запросы не повторяются. Платные модели
OpenRouter для автоматического резерва запрещены. Если ключ резерва не задан,
резерв отключён. Пустой `LLM_FALLBACK_PROVIDER` также отключает его.
Если оба провайдера отказали, лог сохраняет обе ошибки. Участнику сообщается
о временной недоступности сервиса или исчерпании дневной квоты резерва без
внутренних подробностей ответа API.
Для ручного возврата к OpenRouter задайте `LLM_PROVIDER=openrouter` и уберите резерв.
Без `LLM_PROVIDER` сохраняется прежнее поведение — только OpenRouter.

Чат, `/ask`, `/play` и перевод новостей используют общий клиент провайдеров. Память,
системный промпт и проверки прав инструментов работают как прежде. Для чата,
`/ask` и комментария `/play` нет таймера, обрывающего генерацию через 28 секунд:
бот ждёт завершения ответа. Максимум — 650 токенов на обращение к модели;
у переводчика отдельный дедлайн и бюджет. Сброс памяти и удаление или изменение
исходного сообщения по-прежнему отменяют связанный ответ во флудилке.
Незаконченные вызовы инструментов не выполняются.
Размышления отключены через `chat_template_kwargs.enable_thinking=false` у NVIDIA
и `reasoning.enabled=false` у OpenRouter.

11 ноября 2026 года Nemotron 3 Ultra заменена на Nemotron 3.5 Super VL:
прямые запросы к Ultra без истории возвращали бессвязный текст, а уменьшение
температуры не устранило сбой в диалогах. Для Super VL используется температура 0.6;
проверены русские ответы, продолжение диалога и цикл вызова инструмента.
В тот же день подключён прямой API NVIDIA, чтобы не расходовать дневную квоту
OpenRouter при обычной работе бота.
При проверке NVIDIA встречались HTTP 503 (`content safety screening is temporarily unavailable`)
и таймауты. Полный тестовый ответ с серверным эмодзи занял 27,7 секунды;
из-за задержек провайдера прежний 28-секундный таймер генерации убран.
Сетевые ошибки и ограничения самого провайдера всё ещё возможны. Резерв зависит от
оставшейся квоты OpenRouter; при исчерпании обеих возможностей ответ не гарантируется.

По [FAQ NVIDIA](https://build.nvidia.com/api/runtime/content/help-center-faq.yaml)
на 11 ноября 2026 года большинство моделей доступны для прототипирования
с лимитом до 40 запросов в минуту без оплаты за токены. Персональный лимит
указан в панели NVIDIA; постоянная безлимитная квота этим не гарантируется.

Без пополнения у бесплатных вариантов OpenRouter действует общий лимит 50 запросов
в сутки; после покупки кредитов на $10 — 1000, по правилам на 10 ноября 2026 года.
Обычный ответ с проверкой инструментов расходует два запроса; `/play` — один,
а переводы и дополнительные шаги инструментов также расходуют квоту.
Лимиты и доступность бесплатных моделей могут меняться:
[актуальные условия](https://openrouter.ai/collections/free-models).

`BOT_SYSTEM_PROMPT` задаёт дополнительный характер бота. Работа с моделью находится
в `src/llm.ts`, ограниченный цикл инструментов — в `src/llm-agent.ts`, клиент API —
в `src/model-client.ts`. Локальный сервис модели для работы бота не требуется.

## Память и инструменты

Память работает только в канале `1242896006937579522` («🍻-флуд»).

- Обратиться: `/ask`, упоминание бота или ответ (reply) на его сообщение.
- Продолжить конкретный разговор: reply на нужный ответ бота.
- Повторный `/ask` или упоминание без reply подхватывает последний ответ этому пользователю за 30 минут.
- Обычные сообщения записываются локально, без вызова модели. Другие боты и вебхуки игнорируются.
- Запросы из других каналов и лички не получают контекст флудилки.

`/reset` сбрасывает память флудилки. Команда доступна любому участнику из любого канала того же сервера. Ограничение общее для всех: один успешный сброс раз в 30 минут; повторные попытки не продлевают срок. Подтверждение и оставшееся время видит только вызвавший команду.

Сброс очищает сохранённую историю, отменяет текущий ответ с её контекстом и сохраняет в SQLite время сброса. Перезапуск, редактирование старого сообщения и reply на него не возвращают текст до этой границы в память. Reply на старый ответ бота начинает новый разговор. Сообщения участников в Discord сохраняются; запоздавший ответ бота, отправлявшийся во время сброса, удаляется. Системный промпт продолжает задавать обычный характер бота.

В модель передаётся небольшой фон: кандидаты из последних 30 сообщений плюс до 8 сообщений выбранной цепочки. Общий предел — 6000 символов; длинные записи сокращаются. Это не поиск по недельному архиву: бот может не помнить тему, которая выпала из контекста.

При `/ask`, упоминании и reply бот также читает актуальный справочник текущего сервера: участников (включая ботов), имена, выданные роли и явно включённые разрешения каждой роли. Справочник берётся через Discord REST заново при каждом обращении и не сохраняется в SQLite. `/reset` сбрасывает разговор, но не эти сведения о сервере. `/ask` в другом канале получает справочник своего сервера без истории флудилки; личка не получает серверных данных. `/play` и переводчик справочник не используют.

Системный промпт разрешает обсуждать серверные роли, их права, позиции в иерархии и административный статус только по прямому вопросу пользователя или в однозначном продолжении такого вопроса. В обычной беседе бот не должен использовать эти сведения для приветствий, шуток, обращений или сравнения участников, даже если раньше сам уводил разговор в эту тему.

В `/ask`, упоминаниях и reply доступны MCP-инструменты. MCP-клиент и сервер работают внутри процесса бота через транспорт в памяти; внешнего порта и отдельного сервиса нет. Для каждого вопроса создаётся отдельная сессия с автором, сервером и каналом из события Discord. Модель не может передать другого автора или сервер в аргументах. `/play`, переводчик и личные сообщения инструменты не получают.

| Инструмент | Возможность |
| --- | --- |
| `get_member` | Найти участника по ID или имени, получить роли и сведения о нём |
| `list_roles` | Прочитать роли сервера и явно включённые права |
| `get_permissions` | Проверить права участника и бота в конкретном доступном канале |
| `notify_member` | Пинговать одного участника и передать ему сообщение в текущем канале |
| `set_nickname` | Изменить или сбросить ник участника |
| `set_timeout` | Назначить таймаут до 28 дней или снять его |
| `delete_message` | Удалить одно указанное сообщение в текущем канале |
| `set_member_role` | Выдать или снять только Employee (`1242979048917831763`) |
| `create_poll` | Создать встроенный опрос Discord в текущем канале |
| `create_thread` | Создать публичную ветку в текущем текстовом канале, отдельно или у конкретного сообщения |
| `create_reminder` | Сохранить разовое напоминание для автора в текущем канале |
| `list_reminders` | Показать свои ожидающие напоминания и проблемы доставки |
| `cancel_reminder` | Отменить своё напоминание по номеру |

Обращение «начальник» (включая «начальника», «начальнику») закреплено за основным аккаунтом Broromir (`804297985147404328`) в `src/member-aliases.ts`. Второй аккаунт с такой же ролью не делает выбор неоднозначным. Обычная фраза «пингани начальника и спроси, не занят ли он?» запускает поиск основного аккаунта и отправку вопроса с личным упоминанием. Отдельную slash-команду или имя инструмента писать не нужно.

Проверка получателей отделена от текста сообщения: слова после «и» сверяются с реальными участниками, а не со списком разрешённых глаголов. Опечатка вроде «скажы» сама по себе не означает второго получателя. Планировщик получает прошлый диалог как цитируемые данные `past_turn`, чтобы старые отказы бота не выдавались за актуальные ограничения. Отказ модели по содержанию (`DECLINE_CONTENT`) возвращается напрямую, без второй генерации с выдуманным отсутствием возможностей. В журнал пишутся коды отказов и факт ответа без инструментов, без текста переписки.

Адресные сообщения: «Пингани @участник и скажи ему, что собираемся играть», «Позови Alice играть» или reply на сообщение участника: «Пингани его». Имя должно однозначно определять участника; при необходимости модель сначала ищет его через `get_member`. Бот отправляет отдельное сообщение с настоящим упоминанием и затем ссылку-подтверждение. Проверяются членство и доступ получателя к каналу, права автора и бота на отправку; модераторская роль не требуется. Пинг разрешён только одному выбранному участнику в текущем канале. Обычные ответы, роли, `@everyone`, `@here` и остальные упоминания внутри передаваемого текста не создают уведомлений. Повторная отправка при неизвестном результате запрещена; `nonce` защищает от дубликатов. Инструкции обоих этапов модели описывают фактические возможности и запрещают выдумывать отсутствие инструментов или прав до проверки.

Примеры обращений: «Проверь свои права в этом канале», «Смени ник @участник на Космический Кабачок», «Поставь таймаут @участник на 5 минут», «Сними таймаут @участник», «Удали сообщение [ссылка]», «Выдай @участник роль Employee». Для удаления можно ответить на нужное сообщение и упомянуть бота. При неоднозначном имени лучше использовать упоминание или ID. Для изменений участников и удаления сообщения нужна одна прямая команда без вопросительного знака; длительность таймаута указывается целым числом минут после «на». Инструменты поддерживают обычные текстовые каналы и каналы объявлений.

Опросы создаются по обычной просьбе: `создай опрос на 1 час, вопрос — Сегодня играем? ответы 1) Да 2) Конечно, можно выбрать оба варианта`. Кавычки, специальный порядок параметров и шаблон не требуются. Модель разбирает свободный текст, списки и опечатки, сохраняет смысл вопроса, заданные варианты и их порядок. По понятной теме она может сформулировать вопрос и очевидные варианты сама. По умолчанию срок — 24 часа, выбор — один ответ; «сутки», «пара дней», «можно выбрать оба» преобразуются в параметры инструмента. Уточнение нужно только при существенной неоднозначности или неподдерживаемом сроке. Допустимы 2–10 вариантов, вопрос до 300 символов, каждый ответ до 55 символов, целый срок от 1 до 768 часов. Автору и боту нужны `Send Messages` и `Send Polls` с учётом настроек канала. Упоминания отключены.

Для веток: `сделай отдельный тред для обсуждения каток на выходных`. Название до 100 символов модель берёт из темы. Можно попросить ветку к сообщению, приложив ссылку/ID или ответив на него через reply. Источник проверяется по текущему обращению или реальному reply из Discord; модель не может подставить произвольный ID из истории. Создаётся только публичная ветка в текущем обычном текстовом канале, с автоархивацией через 24 часа бездействия и без дополнительного стартового сообщения. Проверяется `Create Public Threads` у обеих сторон, а при привязке к сообщению — также `Read Message History`. Уже существующая ветка не дублируется. После создания опроса или ветки бот возвращает ссылку; они входят в общий лимит одного изменения на запрос.

Намерение создать опрос/ветку и его параметры распознаёт модель; исполнитель проверяет ограничения API, настоящие права и адрес назначения. Короткое уточнение того же автора может завершить уже обсуждаемое создание. Системный промпт запрещает принимать вопрос о возможностях, отрицание, невыполненное условие, цитату или старое сообщение другого участника за новую просьбу выполнить действие. Для операций модерации сохраняется отдельная проверка явной текущей команды в коде.

Перед действием код заново получает роли и участников из Discord, проверяет права автора запроса и самого бота, иерархию и ограничения канала. Роль бота сама по себе не даёт участнику полномочий. Управление Employee требует `Manage Roles` у обеих сторон и подходящей позиции ролей; автоматически права не выдаются. Изменения не запускаются из старых сообщений, цитат или результатов инструментов: нужна явная текущая просьба и указанная цель. Массового удаления нет; сообщение с текущим запросом удалять нельзя.

Для изменения ника, таймаута, удаления сообщения и управления Employee автор запроса дополнительно должен иметь роль `1242978551154868326` или `1278077913899597936`. Владелец сервера и Administrator без одной из этих ролей тоже получают отказ. Проверяется свежий список ролей автора, включая повторную проверку непосредственно перед действием. Это дополнительное условие: обычные разрешения Discord и иерархия всё равно нужны. Чтение данных, опросы, ветки и собственные напоминания этого дополнительного ограничения не требуют. Инструментов бана и исключения участника нет.

Все инструменты используют отдельный короткий системный промпт без характера бота, юмора, каталога эмодзи и полного справочника сервера. Из памяти передаются только до восьми последних реплик текущего диалога (не более 3600 символов, без обрезания отдельных реплик), без общего фона флудилки; текущий вопрос сохраняется целиком. Описания инструментов сокращены до их назначения и важных параметров. Если первый запрос не выбрал инструмент, его черновик отбрасывается и отдельный запрос формирует обычный ответ с прежним характером, памятью и серверными эмодзи. Поэтому обычная беседа с доступными инструментами требует двух обращений к модели; оба используют общий сигнал отмены без фиксированного таймера генерации. `/play`, перевод и обращения без инструментов дополнительного запроса не делают.

На вопрос допускаются до трёх обращений к модели, до четырёх вызовов инструментов и одно действие, меняющее Discord. После действия бот возвращает подтверждение или отказ исполнителя без дополнительной генерации. При неизвестном результате сетевого запроса бот предлагает проверить состояние вручную, не повторяя запись автоматически. При лимите Discord (HTTP 429 или известное ограничение перед отправкой) запись отклоняется без ожидания и скрытого повтора; новая попытка требует нового обращения с новой проверкой прав. Результаты чтения возвращаются модели с тем же коротким промптом для ответа по фактам. Отмена через `/reset`, удаление или изменение текста исходного вопроса останавливает ещё выполняющийся запрос; уже выполненные изменения Discord этим не откатываются. Журнал действий содержит имя инструмента, ID автора/цели/запроса и исход, без текста беседы и токенов.

Чтение участников требует включённого Server Members Intent в Developer Portal; у текущего приложения он уже включён. Для REST не требуется добавлять этот intent в Gateway-подключение или выдавать боту Administrator. Список читается страницами до 1000 участников; весь сбор ограничен тремя секундами внутри общего дедлайна ответа. Справочник ограничен 20 000 символами. Ошибки, таймаут и сокращение явно отмечаются как неполные данные, а не как отсутствие участников или ролей. Права ролей — это базовые разрешения сервера: отдельные настройки каналов, иерархия и ограничения участников в справочник не входят.

Напоминания доступны через те же обращения к боту: «через 40 минут напомни проверить загрузку», «завтра в 20:00 напомни про рейд», «покажи мои напоминания», «отмени напоминание 3». Для модели добавлены `create_reminder`, `list_reminders` и `cancel_reminder`. Время без пояса считается московским; в короткий промпт передаётся текущая московская дата и время. Подтверждение показывает точный срок стандартной отметкой Discord, которую клиент отображает в своём часовом поясе. Поддерживаются разовые напоминания до года вперёд, текст до 500 символов и до 50 одновременно ожидающих заданий на участника сервера.

Напоминание отправляется в исходный текстовый канал с упоминанием только заказавшего его участника. Права автора и бота проверяются при создании и снова перед отправкой. Посмотреть и отменить можно только собственные задания на текущем сервере. Задания хранятся отдельно в `./data/reminders.sqlite` в том же Docker-томе; `/reset` их не удаляет. После перезапуска ожидающие задания сохраняются, просроченные во время простоя отправляются после запуска. Обработчик проверяет сроки каждые пять секунд и не вызывает модель.

Повторная обработка того же обращения не создаёт второе напоминание. До отправки сетевой сбой допускает ограниченный повтор; однозначный лимит Discord тоже переносит попытку. При неизвестном результате отправки или перезапуске в процессе отправки задание получает статус «результат неизвестен» без автоматической повторной публикации. Подтверждённая отправка помечается завершённой, окончательный отказ — недоставленной. Эти проблемы видны при просмотре своих напоминаний. Отменённые и завершённые записи, включая ошибки, удаляются через семь дней. Упоминания ограничены через `allowed_mentions`, повторная отправка дополнительно защищена `nonce`/`enforce_nonce`; срок проверки nonce у Discord ограничен несколькими минутами ([Create Message](https://docs.discord.com/developers/resources/message#create-message)).

База `./data/conversations.sqlite` хранится в существующем Docker-томе `/app/data`. Требуется Node.js 22.13+ с `node:sqlite`. SQLite в Node 22 выводит предупреждение ExperimentalWarning, что не мешает работе. История ограничена семью днями и 500 записями. Очистка выполняется при запуске, при записи и раз в час; сохраняются самые свежие записи.

При запуске подхватываются до 40 последних сообщений канала, созданных после последнего сброса. События редактирования и удаления обновляют память; удаление вопроса удаляет зависимые записи, удаление первого slash-ответа также удаляет сохранённый slash-вопрос. Изменения, произошедшие при выключенном боте, могут остаться незамеченными до истечения срока хранения. Картинки и содержимое вложений не распознаются.

Боту нужны View Channel, Read Message History, Send Messages и включённый Message Content Intent. После обновления нужно зарегистрировать `/reset` обычным скриптом `npm run deploy` (в собранном контейнере — `node dist/deploy-commands.js`).

Для `/ask` и диалогов действует общий лимит: одно обращение одновременно, без очереди. Занятый бот просит повторить вопрос. Фиксированный таймер генерации отключён, рассуждения отключены, ответы компактные. Фоновый переводчик Dev Tracker использует отдельный промпт и не получает память чата; одновременный перевод может увеличить задержку облака.

Для резервного копирования нужно включать Docker-том целиком (для согласованной копии SQLite остановить контейнер либо использовать SQLite backup API); одного образа недостаточно. В логах диагностики не печатается история сообщений.
