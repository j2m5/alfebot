# Диалоги во флудилке

Память работает только в канале `1242896006937579522` («🍻-флуд»).

- Обратиться: `/ask`, упоминание бота или ответ (reply) на его сообщение.
- Продолжить конкретный разговор: reply на нужный ответ бота.
- Повторный `/ask` или упоминание без reply подхватывает последний ответ этому пользователю за 30 минут.
- Обычные сообщения записываются локально, без вызова модели. Другие боты и вебхуки игнорируются.
- Запросы из других каналов и лички не получают контекст флудилки.

`/reset` сбрасывает память флудилки. Команда доступна любому участнику из любого канала того же сервера. Ограничение общее для всех: один успешный сброс раз в 30 минут; повторные попытки не продлевают срок. Подтверждение и оставшееся время видит только вызвавший команду.

Сброс очищает сохранённую историю, отменяет текущий ответ с её контекстом и сохраняет в SQLite время сброса. Перезапуск, редактирование старого сообщения и reply на него не возвращают текст до этой границы в память. Reply на старый ответ бота начинает новый разговор. Сообщения участников в Discord сохраняются; запоздавший ответ бота, отправлявшийся во время сброса, удаляется. Системный промпт продолжает задавать обычный характер бота.

В модель передаётся небольшой фон: кандидаты из последних 30 сообщений плюс до 8 сообщений выбранной цепочки. Общий предел — 6000 символов; длинные записи сокращаются. Это не поиск по недельному архиву: бот может не помнить тему, которая выпала из контекста.

При `/ask`, упоминании и reply бот также читает актуальный справочник текущего сервера: участников (включая ботов), имена, выданные роли и явно включённые разрешения каждой роли. Справочник берётся через Discord REST заново при каждом обращении и не сохраняется в SQLite. `/reset` сбрасывает разговор, но не эти сведения о сервере. `/ask` в другом канале получает справочник своего сервера без истории флудилки; личка не получает серверных данных. `/play` и переводчик справочник не используют.

Системный промпт разрешает обсуждать серверные роли, их права, позиции в иерархии и административный статус только по прямому вопросу пользователя или в однозначном продолжении такого вопроса. В обычной беседе бот не должен использовать эти сведения для приветствий, шуток, обращений или сравнения участников, даже если раньше сам уводил разговор в эту тему.

Чтение участников требует включённого Server Members Intent в Developer Portal; у текущего приложения он уже включён. Для REST не требуется добавлять этот intent в Gateway-подключение или выдавать боту Administrator. Список читается страницами до 1000 участников; весь сбор ограничен тремя секундами внутри общего дедлайна ответа. Справочник ограничен 20 000 символами. Ошибки, таймаут и сокращение явно отмечаются как неполные данные, а не как отсутствие участников или ролей. Права ролей — это базовые разрешения сервера: отдельные настройки каналов, иерархия и ограничения участников в справочник не входят.

База `./data/conversations.sqlite` хранится в существующем Docker-томе `/app/data`. Требуется Node.js 22.13+ с `node:sqlite`. SQLite в Node 22 выводит предупреждение ExperimentalWarning, что не мешает работе. История ограничена семью днями и 500 записями. Очистка выполняется при запуске, при записи и раз в час; сохраняются самые свежие записи.

При запуске подхватываются до 40 последних сообщений канала, созданных после последнего сброса. События редактирования и удаления обновляют память; удаление вопроса удаляет зависимые записи, удаление первого slash-ответа также удаляет сохранённый slash-вопрос. Изменения, произошедшие при выключенном боте, могут остаться незамеченными до истечения срока хранения. Картинки и содержимое вложений не распознаются.

Боту нужны View Channel, Read Message History, Send Messages и включённый Message Content Intent. После обновления нужно зарегистрировать `/reset` обычным скриптом `npm run deploy` (в собранном контейнере — `node dist/deploy-commands.js`).

Для `/ask` и диалогов действует общий лимит: одно обращение одновременно, без очереди. Занятый бот просит повторить вопрос. Дедлайн остаётся 28 секунд, рассуждения отключены, ответы компактные. Фоновый переводчик Dev Tracker использует отдельный промпт и не получает память чата; одновременный перевод может увеличить задержку облака.

Для резервного копирования нужно включать Docker-том целиком (для согласованной копии SQLite остановить контейнер либо использовать SQLite backup API); одного образа недостаточно. В логах диагностики не печатается история сообщений.
