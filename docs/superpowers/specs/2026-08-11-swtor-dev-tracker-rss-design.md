# SWTOR Dev Tracker RSS → Discord

Дата: 2026-08-11

## Задача

Бот периодически (по умолчанию каждые 20 минут) проверяет RSS-ленту раздела Dev Tracker
форума swtor.com и постит новые сообщения разработчиков в заданный Discord-канал —
оригинал на английском плюс перевод на русский, выполненный локальной моделью через Ollama.

## Источник данных

`https://forums.swtor.com/discover/6.xml` — RSS 2.0, ~25 записей, отдаётся без авторизации
(HTML-версия того же раздела возвращает 403, лента — нет).

Поля записи:

| Поле | Содержимое |
|---|---|
| `title` | Заголовок темы форума. Повторяется у разных постов в одной теме. |
| `link` | Прямая ссылка на конкретный комментарий, в CDATA, вида `https://forums.swtor.com/topic/945205-.../?do=findComment&comment=9888802` |
| `description` | Текст поста разработчика в виде обычного текста с HTML-сущностями (`&amp;`, `&quot;`, `&#39;`) |
| `pubDate` | RFC 822, например `Tue, 11 Aug 2026 15:08:45 +0000` |

Автора поста лента **не отдаёт** — в сообщении его не показываем.

Замеренные длины `description` в живой ленте: 9577, 6294, 3063, 2845, 2042, далее меньше 700.
То есть посты регулярно превышают лимит Discord в 4096 символов на `embed.description`.

## Архитектура

Новые и изменённые модули:

| Файл | Ответственность | Зависит от |
|---|---|---|
| `src/rss.ts` | Скачать ленту, распарсить XML, декодировать сущности, вернуть `DevTrackerItem[]`. Про Discord и состояние не знает. | `fast-xml-parser` |
| `src/state.ts` | Прочитать/записать множество ID опубликованных постов в JSON-файл. | `node:fs/promises` |
| `src/text.ts` | `splitText(text, maxLength)` — разбиение по границам абзацев/слов. Вынесена из `index.ts`. | — |
| `src/devtracker.ts` | Оркестрация: таймер → лента → диффинг → перевод → отправка → сохранение состояния. | всё остальное |
| `src/ollama.ts` | Добавляется `translateToRussian(text)`; общий низкоуровневый `chatOllama()` под неё и `askOllama()`. | — |
| `src/index.ts` | В обработчике `ClientReady` вызывает `startDevTracker(client)`. `splitText` теперь импортируется из `text.ts`. | `devtracker.ts`, `text.ts` |

### Типы

```ts
// src/rss.ts
export type DevTrackerItem = {
    id: string          // ID комментария из link, например "9888802"
    title: string       // заголовок темы
    link: string        // прямая ссылка на пост
    text: string        // текст поста, сущности декодированы
    publishedAt: Date   // из pubDate
}
```

### Поток данных одного тика

1. `fetchDevTrackerFeed(url)` → `DevTrackerItem[]` (порядок ленты: от новых к старым).
2. Отфильтровать те, чей `id` уже есть в состоянии.
3. Развернуть в хронологический порядок (от старых к новым), чтобы в канале читалось сверху вниз.
4. Если новых больше 10 — взять 10 самых старых из них, остальные достанутся следующему тику.
   Предохранитель на случай, если лента внезапно отдаст всё заново. На первый запуск
   (см. «Первый запуск») он не распространяется — там количество задаёт `DEV_TRACKER_SEED_POST_COUNT`.
5. Для каждого: перевести → отправить серию сообщений → **сразу** дописать `id` в состояние.

### Дедупликация

Ключ — ID комментария, извлечённый из `link` регуляркой `[?&]comment=(\d+)`.
Заголовок темы для этого не годится: в одной теме бывает несколько постов разработчиков
(в текущей ленте «Issues with EA account link» встречается трижды).

Если `comment=` в ссылке не найден, ключом становится сама ссылка целиком.

## Формат сообщения

Лимиты Discord: `embed.description` ≤ 4096 символов; сумма длин всех embed'ов
в одном сообщении ≤ 6000. Отсюда правило: **один чанк = один embed = одно сообщение.**

Текст поста **не обрезается**. Длинные посты режутся `splitText(text, 4000)`
по границам абзацев (при неудаче — по словам) и уходят серией сообщений:

```
Сообщение 1:  title = заголовок темы, url = ссылка на пост
              description = чанк 1 оригинала
Сообщение 2:  description = чанк 2 оригинала            (без title)
...
Сообщение k:  description = "🇷🇺 **Перевод**\n\n" + чанк 1 перевода
...
Сообщение n:  description = чанк n перевода
              footer = "SWTOR Dev Tracker", timestamp = publishedAt
```

- `title` и `url` — только на первом embed'е серии.
- `footer` и `timestamp` — только на последнем.
- Цвет embed'а одинаковый у всех сообщений серии, чтобы визуально читалось как один блок.
- Между отправками серии — пауза 1 секунда (защита от rate limit).
- Заголовок темы обрезается до 256 символов — это жёсткий лимит Discord на `embed.title`,
  единственное место, где обрезка допустима.

## Перевод

`translateToRussian(text)` в `src/ollama.ts`.

Контекст Ollama по умолчанию — 4096 токенов, поэтому пост на 9.5к символов модель
молча обрежет. Защита:

- Текст режется на порции ~3000 символов той же `splitText` по границам абзацев.
- Каждая порция переводится отдельным запросом, результаты склеиваются через `\n\n`.
- В теле запроса явно передаётся `options: { num_ctx: 8192 }`.
- Таймаут запроса — 240 секунд.
- Системный промпт: переводить с английского на русский, сохранять форматирование
  и игровые термины SWTOR, ничего не добавлять от себя, вернуть только перевод.

Если **любая** порция не перевелась — весь перевод считается неудавшимся, и пост уходит
только с оригиналом и строкой `_перевод недоступен_`. Перевод с дырой посередине хуже,
чем его отсутствие.

## Конфигурация

```
DEV_TRACKER_CHANNEL_ID=          # ID канала. Не задан → фича не стартует (предупреждение в лог)
DEV_TRACKER_INTERVAL_MINUTES=20  # период опроса, по умолчанию 20
DEV_TRACKER_FEED_URL=https://forums.swtor.com/discover/6.xml
DEV_TRACKER_STATE_FILE=./data/devtracker.json
DEV_TRACKER_SEED_POST_COUNT=0    # см. «Первый запуск»
```

Все переменные, кроме `DEV_TRACKER_CHANNEL_ID`, имеют значения по умолчанию.
`.env.example` обновляется.

В `docker/docker-compose.yml` добавляется named volume:

```yaml
volumes:
  - alfebot-data:/app/data
```

Без volume состояние терялось бы при каждом пересоздании контейнера, и бот заливал бы
канал повторно.

## Первый запуск

Первым запуском считается отсутствие файла состояния.

- `DEV_TRACKER_SEED_POST_COUNT=0` (по умолчанию): ничего не постится, все записи ленты
  помечаются виденными. Дальше идут только новые.
- `DEV_TRACKER_SEED_POST_COUNT=N`: постятся N самых свежих записей (в хронологическом
  порядке), **все** остальные помечаются виденными. Нужно, чтобы проверить работоспособность
  сразу после развёртывания, не дожидаясь нового поста разработчика.

Чтобы прогнать проверку повторно, достаточно удалить файл состояния.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Лента недоступна / не 200 / битый XML | Лог ошибки, тик пропускается, состояние не меняется |
| Ollama недоступна или таймаут | Пост уходит без перевода, с пометкой `_перевод недоступен_` |
| Канал не найден или это не текстовый канал | Лог ошибки при старте, планировщик не запускается |
| Нет прав на отправку в канал | Лог ошибки, тик пропускается; бот и слэш-команда `/ask` продолжают работать |
| Падение при отправке 3-го поста из 5 | Первые два уже в состоянии → дублей не будет, оставшиеся уйдут следующим тиком |

Ни одна ошибка Dev Tracker не должна ронять процесс и не должна ломать `/ask`:
тело тика целиком обёрнуто в `try/catch`.

Состояние хранит последние 500 ID (лента отдаёт 25, запас более чем достаточный),
файл записывается атомарно: во временный файл рядом, затем `rename`.

## Планировщик

`setInterval` с периодом из конфига. Первый тик выполняется сразу при `ClientReady`,
не дожидаясь первого интервала. Тики не накладываются друг на друга: если предыдущий
ещё выполняется (долгий перевод), новый пропускается.

## Тестирование

В проекте нет тестовой обвязки. Добавляется встроенный `node:test` (Node 22, ноль
зависимостей), запуск через `npm test`. Покрываются чистые функции, без сети:

- **`src/rss.ts`** — парсинг сохранённого образца ленты (`test/fixtures/devtracker.xml`,
  реальный снимок): корректное число записей, CDATA в `link` не ломает парсинг,
  HTML-сущности декодированы, `pubDate` разобран в `Date`.
- **Извлечение ID** — `comment=9888802` из ссылки; фолбэк на полную ссылку, если параметра нет.
- **Дедупликация** — записи из состояния отфильтрованы, порядок результата хронологический,
  срабатывает предохранитель на 10 постов.
- **`src/text.ts`** — на посте в 9577 символов: каждый чанк ≤ 4096, склейка чанков
  посимвольно равна исходному тексту после нормализации пробелов, разрывы попадают
  на границы абзацев.
- **`src/state.ts`** — round-trip записи/чтения во временном каталоге, обрезка до 500 ID,
  отсутствующий файл читается как пустое множество.

Сеть, Discord и Ollama не мокаются — они проверяются ручным прогоном `npm run dev`
с `DEV_TRACKER_SEED_POST_COUNT=3` в тестовом канале.
