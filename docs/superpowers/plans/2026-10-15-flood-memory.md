# Память флудилки — план реализации

**Цель:** продолжение диалога в канале `1242896006937579522` через `/ask`, упоминание и reply без фоновых запросов к модели.

**Согласованный дизайн:** только один канал; SQLite в `/app/data`; срок хранения 7 дней; последние 30 сообщений плюс максимум 8 сообщений выбранной ветки, до 6000 символов контекста. При старте загрузить до 40 последних сообщений. Другие каналы и личка остаются без памяти. Модель получает авторов и время, но история не становится системными инструкциями. Не читать вложения и картинки. Не отправлять массовые упоминания из сгенерированного текста.

**Технологии:** существующий discord.js, встроенный `node:sqlite` (Node 22.13+), текущая Ollama. Сохраняется дедлайн 28 секунд. Одновременно обрабатывается одно обращение; очередь запросов не создаётся. История и ответы сохраняются только для выбранного канала. Старые записи удаляются раз в час и при старте; дополнительный предел — 5000 записей.

## Задачи

- [x] `src/conversation-memory.ts`, `test/conversation-memory.test.ts`: SQLite, upsert, удаление, срок хранения, изоляция каналов, выделение цепочки и ограничение размера. Проверить сохранение после повторного открытия базы, редактирование и циклические ссылки.
- [x] `src/flood-chat.ts`, `test/flood-chat.test.ts`: пассивная запись, триггеры, загрузка последних сообщений, обработка reply и удаления, защита от параллельных запросов. Не инициировать модель для других каналов/ботов/обычных сообщений.
- [x] `src/ollama.ts`, `src/index.ts`, `test/ollama.test.ts`: передача истории отдельными сообщениями, сохранение slash-вопросов и опубликованных ответов, отключение упоминаний. Проверить отсутствие памяти в переводчике и обычных запросах вне канала.
- [x] Сборка, полный набор тестов, проверка diff и ошибок. Развернуть с резервной копией; проверить SQLite, права канала, запуск и тестовый follow-up через код без публикации тестов в Discord.

## Решения и проверка

- Авторизация реализации и подключения канала дана в диалоге; повторное согласование не требуется.
- Реализация выполняется в текущем рабочем каталоге, исходное дерево чистое. Коммит и push в эту задачу не входят.
- Содержимое чата не выводить в диагностические логи. При проверке продакшена публиковать только счётчики и статусы.
- Reply связывает конкретную цепочку; повторный `/ask` в течение 30 минут подхватывает последний ответ тому же пользователю. Общий фон канала видим всем участникам этого канала.
- События удаления/редактирования обрабатываются и для некэшированных сообщений через partials. Удаление родителя удаляет зависимые записи из памяти. События, пропущенные при выключенном боте, не гарантируются: срок хранения всё равно ограничен.
- Отдельный агент ревью не доступен в текущем наборе инструментов; итоговая проверка выполняется здесь.
- На сервере подтверждены права View/History/Send; SQLite quick_check=ok, сохранены только записи нужного канала. Два тестовых обращения на реальной модели с отдельной временной базой: 3,0 и 12,6 секунды; после повторного открытия базы модель правильно назвала Cucumber-731 и док 17. Тесты в Discord не публиковались.
- Итоговая проверка выявила пустой ответ после удаления выдуманного эмодзи: добавлены регрессионный тест и текстовый fallback для обоих путей отправки.
